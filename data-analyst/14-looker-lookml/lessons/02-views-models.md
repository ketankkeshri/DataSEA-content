# Views Models

Views in Looker are essential for modeling your data effectively, allowing you to create reusable components that simplify complex queries. Understanding how to design and utilize views will streamline your analytics efforts and enable a more organized data exploration process. 

## Understanding Views in Looker

A view in Looker represents a single table or a derived data source. Each view defines a structure that Looker can use to query your data warehouse. It’s where the magic of LookML happens, as you define dimensions, measures, and other attributes that encapsulate your data. 

### Defining a View

To create a view, start with the `view` keyword followed by the name of your view. Below is an example of a view for an `orders` table:

```lookml
view: orders {
  sql_table_name: orders ;;

  dimension: order_id {
    type: number
    sql: ${TABLE}.id ;;
  }

  dimension: order_date {
    type: date
    sql: ${TABLE}.created_at ;;
  }

  measure: total_revenue {
    type: sum
    sql: ${TABLE}.amount ;;
  }
}
```

In this example, we define the `orders` view, specifying the SQL table name and three attributes: `order_id`, `order_date`, and `total_revenue`. The `dimension` and `measure` definitions are critical as they dictate how Looker interacts with your data.

## Connecting Views to Models

Models in Looker are the next step up from views. A model connects multiple views and defines how they relate to each other. Think of it as the blueprint that organizes your views into a coherent data exploration experience.

### Defining a Model

To define a model, you use the `model` keyword. Here's how you can connect the `orders` view to a model:

```lookml
model: ecommerce {
  connection: "my_database"

  explore: orders {
    join: users {
      type: left_outer
      sql_on: ${orders.user_id} = ${users.id} ;;
    }
  }
}
```

In this example, the `ecommerce` model connects to the `orders` view and joins it with a `users` view using a `left_outer` join. This setup allows analysts to explore order data alongside user information seamlessly.

## Common pitfalls

- **Not defining measures or dimensions properly:** Make sure you define your dimensions and measures using the correct types and SQL syntax.
- **Over-joining views:** Be cautious about joining too many views together, as it can lead to complex queries that are hard to maintain.
- **Ignoring performance:** Always review the SQL generated by Looker to ensure it performs well, especially with large datasets.

## In a nutshell

- Views encapsulate data in Looker, defining dimensions and measures.
- Models connect multiple views, allowing for coherent data exploration.
- Pay attention to performance and SQL output when designing views and models.
- Keep joins simple to avoid complexity and potential pitfalls.
